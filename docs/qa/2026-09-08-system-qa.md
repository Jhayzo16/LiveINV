## Confirmed issues, in recommended fix order

### QA-06 — QR lookup can identify the wrong device

**Priority: High.** This occurs when one device's asset tag equals another device's QR ID.

Reproduction:
1. Create device A with asset tag `QA-TARGET-PC` and QR ID `LIV-QA-COLLISION`.
2. Create a newer device B with asset tag `LIV-QA-COLLISION` and a different QR ID.
3. In QR Scanner, look up `liveinv:qr:LIV-QA-COLLISION`.

Expected: device A, because the token explicitly identifies a QR ID.

Actual: device B is identified through its asset tag. The resolver removes the token namespace and takes the first match against either field. The manual lookup was reproduced; the camera uses the same resolver, but physical camera input was not tested. This finding concerns the general QR Scanner, not PMS recording.

Source: `src/pages/SystemPages.tsx:619`.

### QA-04 — Network and Maintenance exports contain the full inventory

**Priority: High.** The downloaded files can misrepresent which devices belong in each report.

Reproduction: open Reports and download Inventory Master List, Network Devices, and Maintenance Report with a mixture of device categories and statuses present.

Expected: each specialized report contains the relevant subset of inventory.

Actual: all three CSV contents were identical, with all nine fixture devices. Network Devices included a non-network monitor, and Maintenance Report included Active devices. Only the filenames differ.

Source: `src/pages/SystemPages.tsx:797` and `src/pages/SystemPages.tsx:800`.

### QA-07 — Blank asset identities can be saved using spaces

**Priority: Medium.** Invalid records can enter the inventory.

Reproduction: open Assets → Add device, choose Router, enter three spaces for Asset tag, Brand name, and Model, then save.

Expected: required-field validation prevents saving.

Actual: the form reports successful registration. Database inspection confirmed empty strings for tag, name, brand, and model. Validation checks string length before the saved values are trimmed.

Source: `src/lib/schemas.ts:8`, `src/lib/schemas.ts:10`, and `src/lib/schemas.ts:11`.

### QA-08 — Recently updated sorts by creation date

**Priority: Medium.** Update an older device, reload the asset list, and select Recently updated.

Expected: the latest updated record appears first.

Actual: the list remains ordered by creation date. In the probe, the oldest fixture device's update timestamp was advanced in the disposable database; reloading did not move it to the top.

Source: `src/lib/repositories.ts:127` and `src/pages/SystemPages.tsx:215`.

### QA-03 — Quick Add new asset does not open the form

**Priority: Low.** Click Add new asset under Quick actions.

Expected: the registration form opens.

Actual: only the All assets registry opens. Another click on Add device is required. Asset registration itself works; this shortcut is incomplete.

Source: `src/App.tsx:174`.

### QA-09 — PMS date search does not recognize the displayed date

**Priority: Low.** With a session displayed as `Sep 8, 2026`, enter that date into Find a session.

Expected: the displayed session is found.

Actual: No matching sessions. Searching `2026-09-08` finds it because the filter searches the raw stored date rather than the formatted date shown to the user.

Source: `src/pages/PmsPage.tsx:29`.
